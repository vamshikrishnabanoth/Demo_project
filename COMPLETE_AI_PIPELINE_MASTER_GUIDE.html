Chapter 1: Executive Overview & The Problem We Solved

1.1 What Does This System Do?

The KMIT Kahoot Platform is an intelligent learning and live assessment platform designed for engineering colleges. It allows a professor to take raw teaching materials—such as a lecture audio recording, a 50-page PDF note, a PowerPoint slide deck, a Word document, or a YouTube video—and automatically converts that material into high-quality, university-standard Multiple Choice Questions (MCQs).

Once the questions are generated, the platform hosts real-time multiplayer quiz battles where over 1,000 students can answer questions simultaneously from their mobile phones or laptops with microsecond response times and live leaderboard updates.

1.2 Why Did We Need a Multi-Agent AI Pipeline?

When most people think of AI question generation, they imagine typing a single sentence into ChatGPT: "Please make 5 questions from this document."

In an engineering university, this naive single-prompt approach fails completely for five major reasons:

  • 1. Hallucination: Generic AI models make up facts, inventing formulas or concepts that were never taught in class.
  • 2. Positional Option Bias: Standard LLMs place the correct answer in Option A over 65% of the time, allowing students to blindly guess Option A and score high.
  • 3. Bad Distractors: The 3 incorrect options are often silly or obvious (e.g. asking "What is TCP?" and offering "A brand of soda" as Option B), making the test too easy.
  • 4. Lack of Cognitive Progression: Real university exams follow Bloom's Taxonomy (starting with basic definitions, then conceptual understanding, then numerical application, and finally deep comparative analysis). Single prompts create random, unorganized questions.
  • 5. Grammatical Giveaways: Prompts often write "an [Correct Answer]" vs "a [Wrong Answer]", giving away the answer before the student even reads the choices.
The Solution (Architecture E): Instead of using one single prompt, we built a 9-Stage Multi-Agent Pipeline. Specialized AI agents divide the work: one agent analyzes the lecture, another maps concept prerequisites, another drafts questions, an independent validator checks for errors, and a final balancer ensures options are distributed equally at 25% each.

Chapter 4: Step-by-Step Deep Dive (Stages 1 to 5)

Stage 1: Multi-Modal Ingestion & Document Router

File: server/engine/documentRouter/documentRouter.js
What it does: Teachers upload different formats. The document router detects the file extension and runs specialized extraction engines:

  • PDF Files: Handled by pdfMultimodalExtractor.js. Extracts text paragraphs and detects embedded images/diagrams.
  • Word Files (.docx): Handled by docxMultimodalExtractor.js using XML traversal to keep headings and bullet points intact.
  • PowerPoint Slides (.pptx): Handled by officeparser to break notes slide-by-slide.
  • Voice Audio & YouTube: Transcribed using Groq Whisper Cloud API to generate timestamped text transcripts.

Stage 2: PDI Routing & Evidence Packaging

File: server/engine/pdiRouter.js & evidencePackager.js
What it does: When a teacher speaks in class while showing a slide deck, spoken words represent Emphasis (what is important for exams), while slides represent Exact Facts (definitions and diagrams). The Pedagogical Delivery Index (PDI) router merges both inputs into an authoritative evidence docket.

Stage 3: Agent 1 — Pedagogical Curriculum Planner

File: server/engine/agents/agent1Planner.js
What it does: Agent 1 acts like a senior university professor designing an exam blueprint. It reads the evidence package and outputs an Assessment Plan without writing actual questions yet:

  • Builds a Concept Dependency Graph (DAG) so foundational ideas are tested before complex ones.
  • Allocates cognitive difficulty across Bloom's Taxonomy:
    • Remember (20%): Direct recall of terms (e.g. "What is the default port for HTTP?").
    • Understand (30%): Explaining mechanisms (e.g. "Why does TCP use a 3-way handshake?").
    • Apply (30%): Practical problem solving (e.g. "Given an IP address and subnet mask, calculate the network ID").
    • Analyze (20%): Comparing trade-offs (e.g. "Under high packet loss, why does Selective Repeat outperform Go-Back-N?").

Stage 4: Dynamic Prompt Builder & Negative Constraints

File: server/config/promptConfig.js
What it does: Assembles the exact instructions sent to the AI. It applies strict negative constraints:

  • Strictly bans: "All of the above" and "None of the above".
  • Length Parity: Enforces that all 4 options have roughly the same character length ($\pm 15\%$) so students cannot simply pick the longest option.

Stage 5: Agent 2 — Creative MCQ Generator

File: server/engine/agents/agent2Generator.js
What it does: Calls the Groq LLaMA 3.3 70B model in structured JSON mode. For every target planned by Agent 1, Agent 2 crafts a complete question with:

  • A clear, scenario-rich question stem.
  • One undeniably correct answer.
  • Three plausible distractors based on real student misconceptions.
  • A detailed pedagogical explanation citing the lecture notes.

Chapter 5: Step-by-Step Deep Dive (Stages 6 to 9)

Stage 6: Deterministic Syntax & Math Healing

File: server/engine/validators/deterministicValidator.js & calculationEngine.js
What it does: AI models sometimes output broken JSON (e.g. forgetting a closing bracket or putting unescaped quotation marks inside mathematical formulas like $E = mc^2$).

Stage 6 uses an Abstract Syntax Tree (AST) Parser that cleans the text, escapes internal quotes, balances brackets, and mathematically calculates numerical values to ensure zero JSON crash errors.

Stage 7: Agent 3 — The 4-Gate Educational Validation Suite

File: server/engine/agents/agent3Evaluator.js & groundingGate.js
What it does: Agent 3 is an independent critic that inspects every generated MCQ against four non-negotiable educational quality gates:

Quality Gate Validation Rule Action if Violated
Gate 1: Grounding Gate Checks if every fact in the question exists in the uploaded document. Zero hallucinated topics allowed. Rejected $\rightarrow$ Routed to Stage 8.
Gate 2: Distractor Plausibility Verifies that all 3 wrong options are realistic misconceptions, not silly or obvious answers. Rejected $\rightarrow$ Routed to Stage 8.
Gate 3: Stem Monotony Gate Ensures question stems are diverse, clear, and don't all start with the exact same repetitive phrasing. Rejected $\rightarrow$ Routed to Stage 8.
Gate 4: Schema Integrity Ensures exactly 4 unique options, a valid correct answer string, and an explanation. Rejected $\rightarrow$ Routed to Stage 8.

Stage 8: Self-Healing Repair Router

File: server/engine/repairRouter.js
What it does: If an MCQ fails Gate 2 because a distractor was too obvious, the system does not throw the question away. Instead, the Repair Router writes a diagnostic error message back to the AI: "Option C is too obvious. Replace Option C with a plausible misconception regarding TCP sequence numbers." The AI fixes the specific field in under 500ms (bounded to maximum 2 repair loops).

Stage 9: Portfolio Assembly & 25% Answer Key Balancer

File: server/engine/portfolioAssembly/
What it does: Solves the famous AI positional bias flaw. Raw AI models put the correct answer in Option A over 60% of the time.

Our algorithm rotates and balances the option arrays across the final quiz so that:

  • Option A: 25% correct
  • Option B: 25% correct
  • Option C: 25% correct
  • Option D: 25% correct

This makes blind guessing mathematically impossible!

Chapter 8: Real-Time Live Multiplayer Engine & WebSockets

8.1 The In-Memory Authoritative Hot Path

When 1,000 students play a live quiz at the same second, querying PostgreSQL for every click will cause the database to crash.

Our platform uses an In-Memory State Machine (server/lib/quizState.js) that holds active quizzes in RAM ($O(1)$ Hash Maps):

  • Grading Latency: $3.1\,\mu\text{s}$ ($0.003\text{ ms}$) in RAM.
  • Throughput: Over $157,000\text{ answers per second}$.
  • Anti-Cheat Duplicate Lock: $O(1)$ Hash Set prevents double clicks or automated bot scripts.
  • Write Coalescing: Score updates are consolidated in memory and flushed to PostgreSQL in batches every 2 seconds, reducing database writes by $95\%$.

8.2 Core WebSocket Event Dictionary

Event Name Type What It Does & Payload Transferred

participants_update io.emit Broadcasts updated live student list to the Teacher Dashboard.
