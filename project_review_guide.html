02. Complete System API Registry

Below is the comprehensive catalog of server endpoints, grouped by features and operational access.

Authentication Routes (/api/auth)

POST /register - Admin-restricted user registration. Creates teacher, student, or administrator records in the database with encrypted passwords.
POST /login - Authenticates users via username/email. Generates a signed JWT payload containing tokenVersion and user role. Blocks duplicate student logins.
POST /register-public - Self-registration path for students. Assigns an initial role of `none` prior to workspace setup.
POST /set-role - Updates and locks a newly registered user's role (`student` | `teacher`). This can only be executed once.
GET /me - Active session validation path. Resolves user authentication status and returns the profile object.
PUT /change-password - Updates user password and increments `tokenVersion` in the DB, immediately revoking all previous JWT tokens to force active sessions to re-authenticate.
POST /forgot-password - Issues a secure, temporary 10-minute password reset token mapped to the user ID.

Quiz & Generator Routes (/api/quiz)

POST /generate - Spawns an asynchronous AI quiz generation task. Returns a unique `taskId` immediately. The parsing handles PDF parsing (`pdf-parse`) and Office formatting.
GET /generate/status/:taskId - Status polling endpoint for background quiz generation tasks.
POST /generate-voice - Generates questions from uploaded audio recordings using the **Groq Whisper API** to transcribe speech to plaintext before calling the generator model.
POST /create - Persists a manual or AI-generated quiz to the database.
GET /my-quizzes - Fetches all quizzes created by the logged-in educator.
GET /result/:quizId - Fetches a student's performance rank and details on completion.
PATCH /:id/schedule - Updates start and end dates/times for scheduled homework assignments.
DELETE /:id - Cascade deletes a quiz and its questions.

Student Portal Routes (/api/students)

GET /gamification - Retrieves XP, login streak metrics, daily missions, and unlocked perks.
POST /gamification/init - Handles streak checks and daily mission resets.
POST /game-score - Submits game results from Sprint or Match-Up. XP is calculated server-side based on questions, duration, and moves to prevent client-side cheat farming.
POST /redeem-perk - Spends student XP to redeem virtual classroom passes, checking monthly limits per ticket.

03. The Generative AI & Agent QA Pipeline

To guarantee high-quality pedagogical assessments, the system does not just call an LLM directly. It executes a structured Agentic Quality Assurance Pipeline.

Interactive QA Pipeline Flow

Stage 1: The Generator (Google Gemini 1.5)

Processes raw plaintext input and generates a draft set of questions, options, and explanations based on the requested count and topic.

Stage 2: The Critic Agent (Rule-Based Expert System)

Scores each question from 0 to 100 based on 6 weighted criteria: Correctness (30 pts), Clarity (20 pts), Distractor Quality (15 pts), Explanation Length (10 pts), Difficulty Alignment (15 pts), and Concept Uniqueness (10 pts). It also flags whole-quiz issues like answer-position bias or repeated concepts.

Stage 3: Early Exit Check Optimization

If the average score of all draft questions is already >= 92, the pipeline skips refinement completely and returns the draft questions. This saves API usage costs and reduces latency.

Stage 4: The Refiner Agent (Llama 3.1 8B via Groq)

Questions scoring below 95 are refined in parallel:
• **Minor Refinement (85-94)**: Only punctuation, explanation length, and formatting are corrected.
• **Full Refinement (<85)**: The question is rewritten based on the specific feedback issues generated by the Critic.

Stage 5: Final Validation & Diff Generation

The Critic re-scores the refined questions. The pipeline returns the finalized questions alongside a structured report showing the quality score improvement (e.g., from 78 to 96) and a visual diff of the modified questions.

04. WebSocket Gateway Communication Protocol

Live classrooms run on a custom WebSocket state room. Below is the protocol matrix:

Event Name Direction Trigger Description
join_room Client → Server Student joins the lobby using a PIN code. Registers presence.
reconnectUser Client → Server Restores student quiz progress from the database after a disconnect.
start_quiz Teacher → Server Teacher starts the quiz. Emits the first question to the room.
submit_question_answer Client → Server Submits an answer choice and checks speed against the lobby average.
answer_feedback Server → Client Emits response speed feedback (cyan or amber popups) to the student.

05. Relational Database Schema blueprint

model User {
id String @id @default(uuid())
username String @unique
email String @unique
password String
role String // 'student' | 'teacher' | 'admin'
isOnline Boolean @default(false)
xp Int @default(0)
dailyMissions Json?
unlockedPerks Json?
createdAt DateTime @default(now())
}
 
model Quiz {
id String @id @default(uuid())
title String
topic String
creatorId String
questions Question[]
isLive Boolean @default(false)
isAssessment Boolean @default(false)
createdAt DateTime @default(now())
}
 
model Question {
id String @id @default(uuid())
quizId String
quiz Quiz @relation(fields: [quizId], references: [id], onDelete: Cascade)
questionText String
options String[]
correctAnswer String
explanation String?
}

Use these key bullet points to highlight the technical achievements of the project during your review:

  • Agentic Quiz QA Pipeline: Emphasize that the platform uses an intelligent Critic-Refiner loop with an early-exit check to ensure high question quality while keeping token usage efficient.
  • 3-Tier YouTube Ingestion Pipeline: Discuss the fallback structure (Transcript → Metadata → Whisper Audio) that ensures 95% of video URLs work seamlessly.
  • Browser Stacking Glitch Resolution: Explain how we resolved Chrome's rounded-corner 3D flattening bug in the Match-Up card game by using explicit transforms, dynamic z-indexing, and opacity cross-fading.
  • Server-Side XP Validation: Highlight the anti-farming rules that validate gameplay duration and matched pairs before awarding XP, preventing students from cheating.
